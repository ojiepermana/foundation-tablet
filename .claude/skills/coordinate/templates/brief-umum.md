# Aturan umum brief: `<nama-SCOPE>`

Bagian tetap dari setiap brief sub sesi koordinasi scope ini. Brief yang dikirim lead menunjuk file ini; brief memperinci tugas dalam batas AC fitur dan aturan bukti.

Untuk lead: isi file ini sekali di langkah 1 SKILL.md, simpan sebagai `docs/scope/coordination/<nama-SCOPE>.brief-umum.md`, dan perbarui saat nilainya berubah (alamat lead, nomor bersama, disk). Butir bertanda `(bawa)` disalin dari file aturan umum scope terakhir (`ls -t docs/scope/coordination/*.brief-umum.md | head -1`) lalu dicocokkan dengan keadaan `main` sekarang. Hapus paragraf ini di file hasil.

- **Alur:** baca brief, file ini, lalu `.claude/skills/coordinate/roles/<peran>.md`, lalu panggil skill yang brief sebut lewat tool `Skill` (bila tool itu tidak ada, baca `~/.claude/skills/<skill>/SKILL.md` dan ikuti), baru bekerja. Bekerja di worktree dan branch yang sudah ada; branch, push, dan PR lain bukan urusan sub sesi. Bila brief menandai "Sesi dipakai ulang: ya", konteks lama sudah dibersihkan: jalankan `git merge main` dulu, lalu pakai brief dan `git log --oneline main..HEAD`. Nama branch bisa warisan item lain; biarkan.
- **Giliran pertama sesi baru:** bila brief menyebut `standby`, hanya baca brief, file ini, dan role, lalu akhiri giliran dengan `STATUS: standby` tanpa mengirim pesan; lead menaikkan effort lalu mengirim "mulai".
- **Checkout utama:** `<path absolut dari git rev-parse --show-toplevel>`. Telusuri file lewat indeks scope, tautan spec dan pencarian repo. Graph dapat dipakai bila tersedia.
- **Alamat lead:** `<nama lead [ref] dari baris pertama ListAgents>`. Laporan lengkap, pertanyaan, dan `needs-decision` dikirim ke sana lewat `SendMessage`. Sub sesi lain dicari di `ListAgents` lewat awal judulnya.
- **Ownership:** hanya file yang tercantum di brief. Lead memegang file scope dan status. Untuk tugas `/audit`, `AGENTS.md` dan dokumentasi konvensi boleh dimiliki sub sesi bila tercantum di brief.
- **Keputusan:** mode `<auto | tanya berat | tanya>` (definisi di `.claude/skills/coordinate/SKILL.md` bagian "Mode keputusan"). Architect mengikuti role-nya dan tetap mengirim ringkasan "Accept this spec?" ke lead, lalu menunggu `accept`. Peran lain: untuk AC yang ambigu baca `rationale.md` spec itu, ambil tafsiran yang paling sesuai teks AC, dan catat di field "Tafsiran AC" laporan; `needs-decision` ke lead hanya bila teks AC atau keputusan spec harus berubah.
- **Langkah manual:** jalankan pemeriksaan yang dapat dilakukan dengan akses yang tersedia. Untuk setiap AC dan target yang belum bisa diuji, catat `NOT_RUN` atau `BLOCKED`, alasan, prasyarat, penanggung jawab, dan cara mengulangnya di file manual. Penutupan AC wajib menunggu bukti `PASS`.
- **Disk:** `<kapasitas untuk build paralel bila relevan>`. Sesuaikan jumlah build penuh dengan kapasitas runner.
- **Proses:** kelola proses uji milik sesi sendiri. Simpan log penting pada lokasi bukti yang dapat diakses dari checkout baru atau melalui CI.
- **Nomor bersama:** `<nomor spec atau kontrak bila diperlukan oleh item, beserta pemiliknya>`. Cocokkan dengan repo dan sesi aktif.
- **Verifikasi developer sebelum melapor:** `<perintah repo yang berlaku bagi target atau dokumen di brief>`. Catat hasil dengan templat laporan per target.
- **Panel skill:** `AskUserQuestion` tidak membangunkan lead, jadi setiap panel dijawab dari daftar ini atau dikirim ke lead. `spec first?` atau `spec gap` → tafsiran sendiri atau `needs-decision` ke lead; "Save verify steps?" = `Save to verify.md` (bagian `## Milestone <n>: <judul>`); tawaran branch atau commit = commit langsung di branch ini; "Run the suite?" = `Yes, run and fix to green`; "No changes" = `Specific files` dari Range perubahan; "Which model wrote this code?" = Model penulis kode di brief; cross check spec = `<dari log Keputusan; default Another model>`; "Track this feature on the scope?" = lewati, blok scope usulan masuk laporan.
- **Commit:** gunakan subject ringkas yang menyebut fitur dan langkah terkait. Untuk milestone dengan spec yang sudah ada, status `Proposed` dapat menjadi `In Progress` saat build mulai.
- **Laporan:** satu laporan akhir per item, tanpa pesan sementara ke lead (aplikasi menahan pesan lead sesudah sekitar 20 pesan), sesuai `.claude/skills/coordinate/templates/report.md`, lewat `SendMessage` ke lead. `done` hanya sah bila semuanya ter-commit, working tree bersih, dan `git merge main` terakhir sudah dijalankan. Sesudahnya panggil `wrap_up` dengan recap yang baris pertamanya `STATUS: ...` dan tulis baris yang sama sebagai baris pertama pesan terakhir; lead hanya membaca 400 karakter pertama.
